# 正式签名与构建

当前版本：0.9.12。正式商店包应使用专用发布密钥，与发到微信的 Debug 包区别管理。

## 现有配置

app/build.gradle.kts 已支持读取 publishing/private/keystore.properties；此目录被 Git 忽略，也不会进入上架材料 ZIP。Release 明确关闭 debuggable，未配置完整密钥时禁止打出 Release APK/签名 Bundle，避免误把未签名包用于提交。仍可独立检查 Release 编译和 lint。

## 密钥准备

正式发布需要创建长期使用的签名密钥，并保存两份离线备份。不要复用开发环境 Debug 密钥，不要把私钥或密码发到聊天、上传到商店材料区或提交 Git。证书摘要可以用于平台登记，私钥不可以。

本人可在 Android Studio 的 Generate Signed Bundle / APK 流程创建密钥，存放于 publishing/private/ruotu-release.jks，别名建议 ruotu。证书主体信息必须真实，不代填个人姓名。长期更新须沿用相同签名。

在 publishing/private/keystore.properties 填写以下键；这是格式模板，不含真实密钥：

```properties
storeFile=publishing/private/ruotu-release.jks
storePassword=本机填写的真实密码
keyAlias=ruotu
keyPassword=本机填写的真实密码
```

使用英文键名、UTF-8/ASCII 值；密码尽量使用足够长的随机 ASCII 字符并正确转义 Java properties 特殊字符。更安全的密钥管理方案可在正式发布前替换；不要因模板存在就认为签名已完成。

## 项目自带工具链构建

还需配置 publishing/private/publisher.properties（UTF-8）：

```properties
developerName=与个人实名一致的姓名
effectiveDate=YYYY-MM-DD
policyApproved=true
```

此文件中的姓名用于最终政策，日期须真实有效。只有本人审阅最终政策并确认实际数据处理与政策一致后，才能将 policyApproved 设为 true。不要把模板占位内容当作真实姓名。未定稿时应用内仅显示带草稿标记的政策检查页面，正式打包会被阻止；已定稿时首次进入 AppRoot 前要求明确同意，政策内容变化后重新确认。同一模板生成应用内文本，后续公开网页也应使用该定稿内容。

在项目目录 PowerShell 中：

```powershell
$env:JAVA_HOME=(Resolve-Path 'toolchain/jdk/home').Path
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:\Users\Administrator\WorkBuddy\DcimRaw\.gradle\sockets'
& .\toolchain\gradle\gradle-8.9\bin\gradle.bat --offline --no-daemon :app:assembleRelease :app:lintRelease --console=plain
& .\toolchain\android-sdk\build-tools\34.0.0\apksigner.bat verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk
Get-FileHash -Algorithm SHA256 app/build/outputs/apk/release/app-release.apk
```

完整准备顺序还包括隐私政策定稿及应用内接入、版权及备案要求确认、真实截图和真机验收。即使正式构建通过，也不自动表示包可提交审核。

## 覆盖安装与数据

新的正式签名与旧 Debug 签名不同，同一包名通常不能直接覆盖安装。不要为解决安装冲突直接卸载含重要编辑记录的测试版：卸载会清除应用私有参数和蒙版。发布前应先规划测试与正式包迁移，或用没有重要数据的独立测试设备验收。导出的 JPEG 保留画面效果，但不等同于备份可继续编辑的蒙版参数。

## 送审核验

检查包名 com.dcimgallery.raw、安装名称“若图”、版本号、arm64-v8a 架构、Release 非 Debug、签名证书摘要；以最终 APK 的合并权限和真实运行行为填写申报。平台签名信息应来自最终发布密钥，而非当前测试包。
